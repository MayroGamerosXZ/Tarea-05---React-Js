Rúbrica de Verificación y Evaluación

Proyecto: Sistema de Taller Mecánico "Command Center" (React.js)

Puntaje Total Máximo: 100 Puntos
Criterio de Evaluación Excelente (20 pts) Bueno (15 pts) Suficiente (10 pts) Debe Mejorar (0-5 pts)
1. Interfaz de Usuario (UI) y Diseño Command Center Implementa a la perfección Tailwind CSS, respetando la paleta estricta (naranja, gris oscuro), aplicando exitosamente el efecto "Frosted Glass" y garantizando accesibilidad y legibilidad. Usa Tailwind y el diseño base, pero falla en detalles menores (como el efecto de vidrio o contrastes de color levemente distintos). El diseño es funcional pero genérico. No respeta la identidad de marca ni las reglas estrictas de UI definidas en la documentación original. La interfaz está rota, desalineada o no se utiliza CSS de forma coherente.
2. Arquitectura SPA y Estado Global (React Hooks) Excelente gestión del useState. La aplicación fluye sin recargas de página, el estado de los vehículos, inventario y buscador se elevan correctamente al componente principal. Maneja estados correctamente, pero con algunas redundancias de código o mala separación de la lógica, aunque la SPA funciona sin recargar. La aplicación recarga, hay fallas al cambiar de pestañas, o los datos introducidos desaparecen al navegar entre vistas. Errores graves de React en consola, o el proyecto no puede compilar bajo el servidor de Vite.
3. Lógica de Negocio: Liquidación y Facturación Interactiva El modal de cobro permite entradas dinámicas, lee repuestos directamente del inventario, calcula subtotales/IVA exactos y descuenta las piezas reales de forma matemática y sincronizada. El modal calcula los totales, pero no descuenta las piezas del inventario real, o no permite ingresar partes dinámicas sino que están fijas. Solo se cambia el estado del vehículo a "Listo" sin ofrecer una calculadora matemática interactiva o desglose de facturación. El botón de cobrar no hace nada o el estado de los vehículos no se puede mutar (cambiar).
4. Módulos Auxiliares: Inventario y Notificaciones El inventario admite Altas, Compras y Mermas (Salidas). El sistema de notificaciones atrapa eventos de toda la aplicación y genera alertas rojas si el stock cae del umbral seguro (minStock). El inventario funcional (CRUD) está bien, pero las alertas o notificaciones no reaccionan en tiempo real al cruzar los umbrales de seguridad. Solo existe una tabla visual de inventario que no se puede alterar (solo lectura), o no existe un centro de notificaciones. Los módulos de Inventario y Notificaciones no fueron construidos.
5. Documentación Completa y Herramientas QA Entrega impecable: Incluye Swagger (OpenAPI), Checklist QA (HTML), Guión de Video, Manual Técnico de Documentación Oficial, y comandos de Git aplicados correctamente. Entrega documentación, pero le faltan los elementos de diseño o el código Swagger no cubre todas las rutas, o no incluye guiones de prueba QA interactivos. Solo entrega un README genérico o un reporte en PDF. No existen herramientas interactivas de prueba para el código frontend. Nula documentación. El proyecto carece de archivos Markdown o HTML descriptivos.

Uso de la Rúbrica:

Imprime o utiliza este documento para asignar la calificación final durante la defensa o exposición en video del proyecto.
